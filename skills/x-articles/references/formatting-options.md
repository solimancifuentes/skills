# Formatting options for X Articles

Choose formats that help the reader follow this particular article. Preserve its subject, argument and requested voice. A plain prose article is a valid result; this inventory is a set of options, not a checklist to exhaust.

## Evidence and currency

- **Official:** [X Help: About Articles](https://help.x.com/en/using-x/articles), checked **October 6, 2026**. It documents the core rich text and media features and discusses a header image.
- **Guide:** [Public formatting demonstration](https://x.com/soliman_cf/article/2106216168738472269), observed in its rendered form **October 3, 2026**. It demonstrates additional formats. This is capability evidence from an article, not an official specification or a guarantee for every editor version.

Features evidenced by the Guide alone are not explicitly enumerated in the checked Help page. Silence in that page does not mean a feature is unsupported. Check the current editor when a selected feature matters.

## Available and demonstrated formats

| Format | Evidence | When it helps |
| --- | --- | --- |
| Headings, subheadings and body text | Official; Guide | Mark substantive transitions and develop the explanation beneath them. Let the material determine the number of sections and paragraph length. |
| Bold, italic and strikethrough | Official; Guide | Emphasize a consequential phrase, distinguish a term, or show an intentional correction. Keep enough ordinary text for emphasis to remain useful. |
| Quoted passages and indentation | Guide; indentation is Official | Separate attributed words or a passage with a distinct role. Preserve exact quotations and identify their source; indentation alone does not establish attribution. |
| Bulleted and numbered lists | Official; Guide | Organize parallel items or a sequence. Use prose when the relationship between ideas needs explanation. |
| Hyperlinks and preview cards | Links: Official; previews: Guide | Link evidence near its claim. Choose a preview when seeing the destination adds context; a link and a rendered card are different outputs. |
| Emoji | Guide | Support tone or navigation when appropriate to the subject and voice. They are optional. |
| Cover/header and inline images | Official; Guide | Establish the topic, show evidence or explain a detail. Choose a relevant cover; supply useful captions and accessible descriptions where applicable. |
| Video and GIFs | Official; Guide | Show motion, an interaction or a process that still images cannot explain as well. Make the surrounding explanation understandable without playback. |
| Embedded X posts | Official; Guide | Place a primary statement or concrete example beside the explanation it supports. Verify the exact URL, author, date and relevant account ownership; distinguish the post's claim from the article's analysis. |
| Dividers | Guide | Mark a meaningful change of mode or section when a heading alone is insufficient. Avoid decorative interruptions to a continuous argument. |
| Code blocks, language labels and syntax highlighting | Guide demonstrated labeled, highlighted JavaScript | Show a mechanism or usable example. Preserve literal code and its language; verify the selected language and highlighting in the current editor rather than assuming every language behaves alike. |
| LaTeX math | Guide | Express a relationship more clearly than prose can. Preserve the formula source and check the rendered symbols and grouping. |
| Tables | Guide | Compare genuinely parallel attributes or present a mapping. Keep cells readable; explain qualifications that need more than a cell. |

## Representation and handoff

A text or Markdown draft can represent headings, emphasis, quotations, lists, links, code, formulas and tables. A standalone verified post URL can mark an intended embed location. Asset references can identify a cover or inline media. These representations do **not** establish that X will import them as native formatting, cards, embeds or media.

When delivering a draft outside the editor, preserve the content and identify any rich elements still to insert or check: placement, exact post or destination URL, media asset and caption, code language, or formula source. Keep preparation notes separate from the article prose. If a requested element cannot be rendered in the current delivery surface, describe the remaining handoff clearly.

When using the editor, inspect the rendered result for the formats actually selected. Verify table structure, code characters, math, link destinations and embedded content as relevant. A successfully rendered article confirms presentation; it does not prove engagement, comprehension or retention.

X's suggested paragraph lengths, heading cadence, editing percentages, emphasis frequency and closing prompts are optional editorial advice. Apply them only when they serve the assignment; they do not require a new voice, an arbitrary shorter article or use of every format.
