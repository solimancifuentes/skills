# Delivering an X Article

When article copy is requested, deliver the complete article, including its title, opening, developed argument and ending. A synopsis, outline or account of what the article would say does not fulfill a writing request. Formatting questions and review requests receive the requested guidance or findings. Preserve the user's selected format and assets; do not shorten or change the deliverable merely because another format is easier to produce.

## Choose the requested delivery mode

- **Full article inline — default.** Show the finished article in the response. Put any essential handoff notes after it, clearly outside the publishable copy.
- **Markdown artifact — when requested.** Save the same complete article text in the requested `.md` file. Keep formatting portable, link the saved file, and distinguish any accompanying handoff notes from the article. If also showing the article inline, use the same text rather than a second, shortened version. A file does not replace a request to show the article here.
- **Native X draft — when requested and accessible.** Use the available browser or editor to create or update the draft. Apply the native formatting and insert the selected embeds or media, then inspect the rendered result. Report what was saved and any features that remain to be inserted. Creating a draft does not authorize publishing, promoting, pinning or replying to it.

No mode requires a particular model, tool, provider, XML structure or JSON manifest. Use the capabilities actually available in the environment.

## Separate article copy from handoff notes

Keep citations and source links that support the article's claims in the publishable copy, near those claims or in the requested end-reference format. Put verification-method notes, asset paths, production-related licensing details and native insertion instructions outside the copy. Preserve links that are an intentional part of the user's prose; do not remove its evidence merely to simplify the handoff.

Keep the article itself portable. Host-specific writing-panel delimiters, internal IDs and interface-control markup do not belong in the copy or exported Markdown. If the host uses a document panel, export its article text and formatting rather than its control syntax. This does not remove requested code, math or other meaningful literal content.

An intended post embed can be represented by its **exact, verified standalone X post URL** at the relevant point in an inline or Markdown draft. Verify the post's text, author and relevance; verify account ownership when presenting it as an official announcement. The URL marks an embed slot: it is not evidence that a native embed has already been inserted. Do not invent status IDs or substitute a profile, search page or unverified post for the selected post. If the post cannot be read, disclose that limitation in the handoff and use a verified alternative only when it serves the same editorial purpose.

Markdown headings, fenced code, math notation and pipe tables are portable representations. Pasting or uploading them does not guarantee X will create the corresponding native blocks. For a native draft, inspect the available editor controls, apply the supported representation and verify the rendered result. For a handoff, identify any native steps that remain; keep those instructions out of the article body.

## Assets and unavailable capabilities

Use a cover or other media when requested or when it has a clear editorial purpose. Imagery is optional. Respect user-selected assets and formats; use assets the user can publish, and do not treat a search result as permission to reuse it. If an asset is unavailable, describe the missing piece outside the copy without claiming it was created or inserted.

When browsing, generation or editor access is unavailable, finish the work those capabilities do not prevent and explain the concrete limitation. If native drafting is unavailable, deliver the full article inline or in a requested artifact, with a simple handoff for the remaining editor steps. Do not describe a local file as an X draft or call unverified links, rendering or uploads complete.

Before changing an already published Article, check the [current X Help guidance](https://help.x.com/en/using-x/articles) and the live editor confirmation. The documented edit flow unpublishes the Article before it can be edited and republished (checked October 6, 2026). Preparing revisions alone does not authorize that publication-state change.

## Small handoff example

**Article copy**

> # A shorter queue
>
> A queue becomes easier to manage when every item has a clear next step. Without one, the same request returns for another round of discussion.
>
> Start by assigning an owner and naming the next action. Review what is still waiting a week later. Count how many requests moved forward; that tells you whether the change helped.

**Handoff notes — excluded from the article**

- Use the first line as the native title and keep the two body paragraphs intact.
- Insert the user's selected queue chart after the first paragraph. If the chart is unavailable, report that omission; do not paste this instruction into the body.
