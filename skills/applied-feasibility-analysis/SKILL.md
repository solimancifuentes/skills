# Applied Feasibility Analysis

## Goal

Distinguish an interesting external idea from one that should actually be adopted by the target project. Ground every material conclusion in traceable subject evidence and verified target-project facts. Analyze only; never treat a recommendation as authority to change the target project.

## Route the request

Choose one mode from the task shape:

- **Atomic Analysis:** Use for one bounded capability, implementation, mechanism, or practice from an article, paper, repository, memo, claim, or other source. Read [references/evidence-and-decisions.md](references/evidence-and-decisions.md) and [references/atomic-analysis.md](references/atomic-analysis.md).
- **Business Surface Analysis:** Use for one company/product and a broad project-relative learning or adoption objective spanning one or more business surfaces. Read [references/evidence-and-decisions.md](references/evidence-and-decisions.md) and [references/business-surface-analysis.md](references/business-surface-analysis.md).

Reuse candidate selections, objectives, evidence boundaries, scope, and output paths already supplied or confirmed. Ask only when consequential information remains unresolved after inspecting available context. Do not silently turn a generic profile or summary request into a feasibility analysis.

When an Atomic source contains materially different candidates, keep the user's selected candidate. If the intended candidate remains unclear, present a concise candidate list and ask which bounded thesis to evaluate. Evaluate all only when explicitly requested as a portfolio; never collapse several candidates into one verdict or score.

## Establish the inputs

Require:

1. **Subject evidence:** sources for the selected Atomic candidate, or the verified company/product identity and authorized evidence boundary for Business Surface mode.
2. **Target project:** a project path or sufficient project context.
3. **Decision objective:** the project-relative question the analysis must answer.

Retrieve the actual sources. Read manageable, bounded supplied documents completely; for repositories and large documentation collections, inspect the selected mechanism and its relevant dependencies, prerequisites, and limitations. Apply the shared contract's coverage and provenance rules. If evidence is inaccessible, preserve supported findings and candidates; withhold only verdicts that lack decision-critical evidence. Never reconstruct an unsupported mechanism from a title or excerpt.

When a target-project path is available, inspect its authoritative read order and relevant files before asking questions. Record a cited project fact sheet for the run, including the state inspected. Ask only for consequential facts that cannot be discovered, and state how each missing fact affects the assessment.

## Apply the shared boundaries

- Trace every material subject and project claim to evidence.
- Label material inference and uncertainty without mechanically tagging every directly cited sentence.
- Use assessment status, verdict, and confidence exactly as defined in the shared contract.
- Do not use a numerical fit score or average candidate decisions into a company score.
- Keep recommendations, validation proposals, and implementation authority separate.
- Permission to inspect private evidence does not authorize public disclosure. Minimize confidential material in the report and mark it confidential when the intended audience or sharing context makes that distinction relevant.
- Do not modify the target project, publish, install a dependency, contact anyone, or execute a recommended adoption unless the user separately authorizes that action.

## Deliver

- **Atomic:** Present the report inline. Save only when requested, using the supplied or confirmed exact directory and filename without asking again.
- **Business Surface:** Use a dated dossier by default; resolve its path before writing. An explicit inline request needs no path and creates no files, while retaining the analytical content defined in the Business reference. For a dossier, present the synthesis and exact path in the conversation.

Resolve a missing output path before writing; independent authorized research may continue while it is unresolved. Preserve existing files and never silently substitute a different exact destination. Follow the Business reference's collision rules for generated dossier paths.

Leave historical analyses unchanged. Apply this contract only to new runs.
